## أداء SAP: ما قِيس وما تعذر

### الاتصال الحي

الإعداد متوفر ويستخدم HTTPS، لكن **التحقق من شهادة TLS معطّل**؛ لذلك لم يُستخدم SAP الحي، رغم وجود تفويض سابق للقراءات. لم أغيّر إعداد الاتصال أو أطلب أسرارًا أو أنقلها للمحادثة. [فحص السلامة المنقح](../scratch/handover-current-review/connection-safety.json) يحتفظ بأعلام فقط، دون المضيف أو الشركة أو بيانات الاعتماد. جميع قياسات هذه المهمة معزولة، ولا يوجد توقيت SAP حي جديد.

### مقارنة الخوارزميات الموجودة

المقارنة التالية **ليست قبل/بعد تعديل جديد**؛ تشغّل مسار القراءة الفردية المرجعي والمسار المجمع الموجود في النسخة الحالية على نفس البيانات المصطنعة. 10 سجلات، وتأخير نقل مصطنع 2ms لكل نداء، وصفحة تجريبية من 5 سجلات؛ 30 عينة لكل صف. P95 بطريقة nearest-rank. يُمنع أي HTTP حقيقي، بما فيه fallback غير المتوقع.

| العملية / المسار | النداءات | متوسط wrapper ms | الوسيط ms | P95 ms | الأخطاء / المهلات |
|---|---:|---:|---:|---:|---|
| خصائص تتبع الأصناف — فردي مرجعي | 20 | 50.197 | 50.054 | 52.135 | 0 / 0 |
| خصائص تتبع الأصناف — bulk الحالي | 2 | 5.396 | 5.302 | 5.856 | 0 / 0 |
| مرشحو أوامر البيع/التسليم — فردي مرجعي | 10 | 25.344 | 25.417 | 25.870 | 0 / 0 |
| مرشحو أوامر البيع/التسليم — batch الحالي | 2 | 5.475 | 5.476 | 6.218 | 0 / 0 |

النتائج متكافئة داخل العينات. عدد 2 نداء يعتمد على حجم الصفحة التجريبي؛ ليس إعادة إنتاج أو تأكيدًا لأرقام 20→5 أو 3.10s→809ms المرجعية. لا يُعلن تحسن زمن SAP الفعلي من هذه الأرقام.

استُخدم `PerformanceMiddleware` الحقيقي حول handler اختبار يستدعي خوارزمية القراءة، مع spans تحاكي نقل SAP وتُقاس حول الانتظار الفعلي المصطنع:

| العملية الحالية | وسيط middleware ms | وسيط spans النقل المصطنع ms |
|---|---:|---:|
| bulk خصائص الأصناف | 5.030 | 4.480 |
| batch مرشحي المستندات | 5.220 | 4.705 |

هذا **ليس endpoint تشغيليًا كاملًا** ولا اتصال Service Layer حقيقيًا. wrapper يتضمن إنشاء طلب الاختبار واستدعاء middleware، بينما total داخل middleware لا يتضمن نفس الغلاف؛ لا تُجمع medians أو تُطرح لتكوين تقسيم إنتاجي مزعوم. [التفاصيل والمنهج](../scratch/handover-current-review/performance.json).

لم يُضف cache جديد أو يُغير TTL أو تصفية/ترقيم النتائج. فحص المصدر أكد وجود pooling مع منع cookies المخزنة وقراءة مرشحين على دفعات ودمج loaders المتزامنة سابقًا؛ اختبارات الصحة في النطاق المعلن أُعيدت، لكن لم يُقَس كل master-data endpoint زمنياً أو يُجر حمل متعدد workers.

## الهوية البصرية والهيدر

المسارات الحالية روجعت من Router والمصادر، ثم فُتحت فعليًا:

- عروض البيع `/customization-delivery/quotations`.
- أوامر البيع `/customization-delivery/orders`.
- التسليم `/customization-delivery/deliveries`.
- التسكين `/shipping-loading`، مع تحويل `/transfer/shipping` إليه.

المراجع هي `/production` و`/quality` وPageHeader/card-panel/app-button ورموز المشروع العامة. بطاقات `SalesDocumentCard` والفلاتر وملخصات الكميات المرنة موجودة، كما أن تفاصيل الأنواع الثلاثة تستعمل الجدول المشترك بالفعل، وصفحة التسكين تستعمل رموز السطح والحدود والألوان القائمة. لم يظهر سبب لإعادة تصميمها أو حذف حقولها أو إضافة قوائم داخل Pricing Wizard.

المصفوفة الجديدة **العربية/الإنجليزية × الفاتح/الداكن × 320×640، و768×900، و1440×900**: 48 حالة للشاشات الأربع، و24 للمراجع، و36 لتفاصيل المستندات الثلاثة. اختُبر داخلها تبويب مسودة التسليم، وخطوات اختيار أمر وعربية وحاوية في التسكين، وبقاء الحاوية المختارة وظهور صنف جدول المستند. لم تُحفظ أو تُرسل بيانات بيان تحميل أو تُختبر عمليات وزن.

الهيدر فُحص مستقلًا بعرض 320/768/1024/1101/1280/1440/1920 باللغتين مع إطالة المسار عمدًا: صف الديسكتوب ثابت، صفا التابلت ثابتان، ولا تجاوز للقائمة. النصوص تبقى في DOM وروابطها؛ الاختصار بصري، ولا توجد دعوى إضافة وسيلة عرض كاملة جديدة للمسار أو اختبار كل وسائل الوصول.

### غير منفذ والموانع الباقية

1. أخطاء Fast Refresh الثلاثة ما زالت مانع الجودة. لا تعديل للمستهلكين المحميين أو exports غير متحقق منها، ولا ادعاء إغلاقها بسبب نجاح runtime.
2. النطاق المحمي وترجمته واختباراته وexecutable لم تُراجع أو تُختبر، بما فيها الحالات في الملفات المشتركة؛ قوائم الاستبعاد السابقة لا تتحول إلى نجاحات أو skipped. لا اختبار ميزان/ScaleAgent/توقيع/تنزيل/بصمة/تذكرة أو وزن فعلي.
3. لا قياسات SAP حية أو مقارنة إنتاجية قبل/بعد؛ التحقق من TLS يحتاج قناة موثوقة وإجراء مستقل قبل القياس الحي. القياسات الحالية synthetic/local فقط.
4. لا React Profiler مستقل، ولا اختبار حمل/Redis متعدد العمال أو كل العملاء والأصناف والمخازن ومراكز التكلفة ببيانات SAP حقيقية. لا زمن موحد لكل endpoint في المشروع.
5. لا اختبار شامل لكل الشاشات والرحلات والصلاحيات؛ لا إعادة PDF/طباعة أو UAT الأجهزة والباركود، ولا حفظ/اعتماد/ترحيل حقيقي.
6. لا تحقق نشر أو استعادة backup أو تطبيق migrations على التشغيل. Git ما زال يحتوي العمل السابق وملفات غير متتبعة؛ يلزم artifact كامل معتمد، لا نشر HEAD بافتراض أنه النسخة المختبرة.

التحسينات المرجعية منطبقة بالفعل في الأجزاء التي أمكن إثباتها. النتيجة العملية هي تحقق حديث وحدود واضحة، وليست نقلًا أعمى أو تحسينًا إنتاجيًا جديدًا أو موافقة نشر.
